# מודל ההתקדמות המשותף — שלב 2

המודל הוא תשתית נתונים בלבד. הוא אינו מוסיף NPCs, ערוגות או מסכי אפייה.
לא ניתנים פריטי התחלה או פרסי סיפור אוטומטיים.

## מקור הנתונים

- `game/progress/state.js`: מבנה גרסה 1, אימות, העברה מהשמירה הישנה ופעולות נתונים.
- `game/progress/store.js`: מופע משותף למסך, ארנק ומזהי פעולות.
- השמירה הקובעת: `localStorage.popaProgressV1`.
- `popaWorldV1` נשמר כמראה לתאימות. העברה ממנו מתבצעת רק כשאין שמירה קובעת.
  נשמרים המטבעות, שיא וסיבובי הגינה, השטיח, הבגד ומזהה פרס המניקור האחרון.
- הגינה, המספרה והמניקור כותבים כעת לאותו מקור נתונים. שינוי בגד או קניית שטיח
  מתבססים על המצב העדכני ואינם שומרים עותק ישן של הארנק.
- אלבום התסרוקות, ציורי המניקור ב־IndexedDB וסידורי חדר/סטודיו נשארים במאגרים
  הייעודיים שלהם. הם לא נמחקים ולא הופכים למצב משימה.

## שדות

| שדה | תוכן התחלתי |
| --- | --- |
| `wallet.coins` | הארנק הקיים או אפס |
| `inventory` | כמויות לפי מזהה פריט; ריק |
| `home.rug`, `appearance.outfit` | הבחירות הקיימות |
| `activities.garden` | שיא ומספר סיבובים קיימים |
| `activities.manicure` | מזהה הפרס האחרון, לתאימות |
| `story.firstCake` | `not-started`, שלב `meet-milli` |
| `story.npcs` | מילי ובוני: היכרות ושיחות שהושלמו; טרם נפגשו |
| `farming.plots` | ערוגות, גידול, מצב וזמני שתילה/השקיה/מוכנות/קציר; ריק |
| `recipes.completed` | מונה הכנות לפי מתכון; ריק |
| `receipts` | פעולות שכבר בוצעו, עם זמן ביצוע |
| `revision`, `updatedAt` | גרסת העדכון וזמן השמירה |

שלבי המשימה הראשונה: `meet-milli` → `grow-strawberries` →
`bake-with-bonnie` → `deliver-cake` → `completed`.
הזמנים הם מילישניות מאז Unix epoch. המודל אינו מפעיל טיימר גדילה בעצמו.
אין עדיין כללי מתכון, תנאי השקיה, XP או רמות. המערכות הבאות יקבעו אותם.

## פעולות נתונים

```js
import {progressStore} from './game/progress/store.js';

// מזהה יציב לאותה פעולה: בניסיון חוזר מתקבל applied:false.
const result = progressStore.commit('quest:first-cake:start', {
  npc: {id: 'milli', dialogue: 'first-meeting'},
  quest: {action: 'start'},
});

// דוגמת מסירה בלבד: ניתן להפעיל רק כשהמשימה בשלב המסירה ויש עוגה.
progressStore.commit('quest:first-cake:delivery', {
  consume: {'strawberry-cake': 1},
  coins: 20,
  quest: {action: 'complete-step', expectedStep: 'deliver-cake'},
});
```

כמות הפריטים וסכום הפרס בדוגמה אינם החלטת איזון למשחק.
כל שינוי בפעולה נבדק על עותק, ורק אז נכתב צילום מצב אחד. חוסר בפריטים,
מטבעות שליליים, שלב לא תואם או נתון פגום מבטלים את כל הפעולה. מזהה הפעולה
והשינוי נשמרים יחד, ולכן מסירה חוזרת עם אותו מזהה אינה נותנת פרס נוסף.
משימה מתקדמת שלב אחד בכל פעם. כללי העולם, כגון האם אכן בוצע קציר או אפייה,
עדיין צריכים להיבדק במערכות המשחק הקוראות למודל.

`commit` מחזיר `applied`, `persisted` ו־`state`. אין להציג שמירה מוצלחת כש־
`persisted` הוא false. במצב חסימת אחסון נשמר ביקור זמני בזיכרון בלבד.
שמירה פגומה או מגרסה חדשה יותר אינה נדרסת; ניתן לייצא את הנתונים הקיימים
ישירות מהדפדפן לפני טיפול ידני. אין איפוס אוטומטי של הקובץ הבעייתי.

`read()` מחזיר עותק. `exportJSON()` ו־`importJSON()` מאפשרים גיבוי וטעינה
בתכנות; אין בשלב הזה כפתורי ייבוא/ייצוא חדשים בממשק. `subscribe()` מאפשר
למסכים הבאים להאזין לפעולות באותו מופע; אינו מנגנון סנכרון שרת.

## גבולות השמירה

זהו מתאם מקומי ללא חשבון, שרת או סנכרון בין מכשירים. הוא קורא נתונים עדכניים
לפני פעולה כדי להימנע מדריסת ארנק בעת מעבר בין מסכים. localStorage אינו מסד
נתונים עם נעילה בין לשוניות: כתיבות סימולטניות לחלוטין עדיין מחייבות מנגנון
נעילה או מתאם שרת בהמשך. אין כאן הגנה מפני עריכת נתונים בצד הלקוח.

מניעת תגמול חוזר חלה על מזהי פעולות שנשמרו. השמירה הישנה זכרה רק את ביקור
המניקור האחרון, ולכן אי אפשר לשחזר ממנה היסטוריית פרסים שלא נשמרה מעולם.
